# Поиск кандидатов для объявлений Avito

Задача решения: для каждого поискового запроса найти до 50 подходящих объявлений из `benchmark_items.parquet`.

Итоговый результат на платформе: **Recall@50 = 0.810255**

Результат на локальной проверке: **Recall@50 = 0.832246**

## Какие данные и признаки использованы и почему

Для запроса использованы:

- `search_query`, основной текст запроса
- `search_location_id`, помогает сначала искать объявления в нужной локации
- `search_infm_params_text`, содержит дополнительные фильтры, например вид или тип услуги

Для объявления использованы:

- `item_title_raw`, коротко и точно описывает услугу
- `item_infm_params_text`, содержит тип и параметры услуги
- `item_description_raw`, помогает найти совпадения, которых нет в заголовке
- `item_location_id`, нужен для разделения локального и глобального поиска

Заголовок объявления получил больший вес в BM25, потому что в нем обычно находятся самые важные слова.

Из строки фильтров удаляются названия полей вроде «Тип услуги» и «Вид услуги». В запросе остаются только полезные значения фильтров.

Категория почти не разделяет объявления в benchmark, поэтому она не вошла в финальный поиск. Цена, рейтинг и признаки доступности контактов больше описывают условия и качество исполнителя, а не соответствие услуги тексту запроса, поэтому они тоже не использовались.

## Какие модели или алгоритмы применены

Решение состоит из двух поисковых частей.

### Dense поиск

Использована open-source модель `intfloat/multilingual-e5-small`.

При первом запуске библиотека скачивает открытые веса модели. После этого обучение, построение эмбеддингов и поиск выполняются локально.

Модель дополнительно обучается на парах «поисковый запрос, выбранное объявление» из `train.parquet`.

Основные параметры обучения:

- `MultipleNegativesRankingLoss`
- не больше трех положительных объявлений на один нормализованный запрос
- одна эпоха
- batch size 64
- learning rate `2e-5`
- максимальная длина 256 токенов

Текст запроса передается модели с префиксом `query:`. Текст объявления собирается из заголовка, параметров и описания с префиксом `passage:`.

Эмбеддинги нормализуются. Похожесть запроса и объявления считается обычным скалярным произведением.

### BM25

BM25 ищет точные совпадения слов и дополняет dense поиск.

В текст объявления для BM25 входят:

- заголовок, повторенный три раза
- параметры объявления
- начало описания

Для русского текста используются стемминг и стоп-слова. Реализация: `bm25s==0.3.11` и `PyStemmer`.

### Объединение результатов

Финальные 50 кандидатов собираются так:

- 32 объявления из локального dense поиска
- 14 новых объявлений из локального BM25
- 4 новых объявления из глобального BM25
- если мест не хватило, остаток заполняется глобальным dense поиском

Повторы удаляются во время объединения.

## Как проверялось качество решения до отправки

Из `train.parquet` детерминированно собрана отдельная выборка из 2 452 запросов.

Все строки с теми же нормализованными текстами запросов исключались из обучения E5, чтобы модель не видела тексты проверочных запросов во время обучения.

Для каждого варианта считались:

- Recall@50, основная метрика задания
- HitRate@50, доля запросов, где найдено хотя бы одно подходящее объявление

Сначала проверялась исходная E5-small без дополнительного обучения. Затем сравнивались дообученная модель, BM25 и разные квоты поисковых каналов.

Лучший zero-shot гибрид получил Recall@50 `0.807844`. После дообучения E5-small результат вырос до `0.832246`.

Перед сохранением `answer.csv` код отдельно проверяет:

- наличие всех `query_id`
- отсутствие лишних и повторяющихся `query_id`
- существование каждого `item_id` в корпусе
- формат `item_id`
- отсутствие повторов внутри ответа
- ровно 50 кандидатов на запрос
- наличие только колонок `query_id` и `answer`

## Какие типы ошибок найдены и что с ними сделано

### Фильтры ухудшали dense поиск

Если добавлять всю строку `search_infm_params_text` в dense запрос, качество становилось хуже. Причина в повторяющихся названиях полей и служебных словах.

В финальном решении dense модель получает только `search_query`. Очищенные значения фильтров добавляются только в BM25.

### Часть подходящих объявлений находилась в другой локации

Среди 420 пропущенных объявлений 279 находились не в точной локации запроса.

Поэтому решение использует не только локальный поиск, но и отдельный глобальный BM25 канал. Простое увеличение глобальной квоты ухудшало средний Recall@50, поэтому была оставлена небольшая квота из четырех глобальных кандидатов.

### Исходная и дообученная E5 находили разные объявления

Было проверено объединение zero-shot и fine-tuned E5-small. Оно не улучшило Recall@50 и выбрало те же квоты, что и вариант только с fine-tuned моделью.

Поэтому в финальном решении оставлена одна дообученная E5-small без лишнего ансамбля.

## Что находится в каждом notebook

### `01_train_and_validate.ipynb`

Этот notebook:

1. читает `train.parquet` и benchmark-файлы
2. создает отдельную validation выборку
3. исключает validation запросы из обучения
4. дообучает E5-small
5. строит эмбеддинги объявлений
6. получает dense и BM25 выдачи
7. сравнивает разные квоты
8. сохраняет модель, эмбеддинги и таблицу метрик

Если обучение или построение эмбеддингов уже завершено, notebook проверяет сохраненные настройки и использует готовые артефакты.

### `02_generate_answer.ipynb`

Этот notebook:

1. загружает сохраненную модель и эмбеддинги
2. кодирует запросы из `benchmark_queries.parquet`
3. строит локальную и глобальную dense выдачу
4. строит локальную и глобальную BM25 выдачу
5. объединяет кандидатов по квотам `32/14/4/0`
6. проверяет формат результата
7. сохраняет `answer.csv`

## Как запустить решение

Для запуска нужны Python 3.10 или новее и компьютер с CUDA GPU.

Структура папки:

```text
Avito_test_task/
├── datasets/
│   ├── train.parquet
│   ├── benchmark_queries.parquet
│   └── benchmark_items.parquet
├── 01_train_and_validate.ipynb
├── 02_generate_answer.ipynb
├── requirements.txt
└── README.md
```

Порядок запуска:

1. установить зависимости из `requirements.txt`
2. открыть `01_train_and_validate.ipynb` из корня проекта
3. выполнить все ячейки сверху вниз
4. открыть `02_generate_answer.ipynb` из того же корня проекта
5. выполнить все ячейки сверху вниз
6. забрать созданный файл `answer.csv` из корня проекта

Модель работает локально. Внешние API для получения эмбеддингов или поиска не используются.
